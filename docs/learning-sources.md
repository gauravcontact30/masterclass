# Learning scopes and documentation

The dashboard requests `/api/catalog?technologyId=...` whenever a technology is selected. It clears the previous scope immediately, displays loading/error/empty states, and ignores stale responses. Catalog reads paginate until empty so the database row cap cannot hide later topics. Every existing topic for the selected technology is returned, grouped into complete paths and single topics.

The catalog is curated in `supabase/seed.sql` and migrations `0004`, `0006`, `0007`, and `0008`. Apply pending migrations to the deployed Supabase database to expose those topics. This does not claim to enumerate every page or topic on the internet; new scopes require catalog entries with reviewed documentation references.

Before generating a new curriculum, the worker fetches the scope's documentation references. Only maintained HTTPS documentation hosts are accepted; redirects are checked, time and response sizes are bounded, and scripts/navigation are excluded from HTML extracts. Some publishers serve Markdown directly. C++ currently uses the authoritative community reference cppreference, rather than claiming it is a vendor-owned site.

The fetched excerpts are passed to the model for original explanations and exercises. Missing/unusable references fail the job through the existing retry system, rather than silently generating without sources. No fetcher can guarantee that an AI explanation is error-free. Source URLs, titles, and retrieval dates are stored with the curriculum and included in exported PDF, PowerPoint, and notes. The reuse key includes `sources-v1` so older, ungrounded cached documents are not reused for new requests.

JavaScript-only documentation shells, paywalls, unsupported redirects, or stale reference URLs need a reviewed replacement in the catalog. A full-path reference must contain enough substantive documentation to support that path; the model is instructed to decline insufficient excerpts. Fetching is performed by the existing generation worker, which still requires configured Anthropic credentials. No schema migration is needed for provenance because the curriculum column already stores JSON.

Public samples contain five focused pages: goals, three worked examples, and a practice project. Notebook notes shows those same five sections with pagination and a full text download. The sample IDs are versioned so old saved page positions cannot exceed the new page count. Public sample previews are generated at 2× resolution (`npm run samples`): slides are 2560×1440 and PDF cover images are 1588×2246. The PDF reader renders the actual PDF at high pixel density; slides use the full-resolution PNG previews; Notes uses selectable HTML text and a public text download. Sample files remain illustrative fixtures, not newly generated live documentation lessons.
